Architecture & contributing

DevTree is small enough to read in an afternoon: a Rust server that runs git, and a dependency-free web UI. Here is how it fits together, and how to work on it.

Ways to help

  • Try it on your repositories and report what breaks, including the Console output if it helps.
  • Fix a bug or build a feature. Open an issue first for bigger changes, so we can agree on the approach.
  • Improve these docs: they live in site/ in the same repository.

Development setup

$ git clone https://github.com/ErmanDev/DevTree.git
$ cd DevTree
$ cargo run -- --port 7979   # debug build, on another port

The UI files in web/ are compiled into the binary with include_str!, so rebuild (or re-run cargo run) after editing them.

Architecture

The browser talks JSON to a local axum server. The server runs the real git program for every operation and parses its machine-readable output. There is no libgit2 and no database.

Backend (src/)

FileResponsibility
main.rsStartup, flags, routes, the localhost and header guards, repository, graph, status, diff and pull/push handlers. It also dispatches the helper modes.
api.rsShared handler plumbing: app state, the JSON error type, and input validation (refs, SHAs, paths).
git.rsRuns git (timeouts, cancel, streamed progress, killing the whole process tree). It also parses log, status, refs, blame and name-status output, and detects in-progress operations.
graph.rsLane layout for the commit graph (see below).
actions.rsConflicts, discard, stash, merge/rebase, branches, tags, cherry-pick/revert/reset, remotes, file previews, applying patches.
explore.rsFile history, blame, search across history, compare.
rebase.rsInteractive rebase: the plan endpoint and the editor helper modes.
net.rsNetwork commands: progress jobs, cancel, the per-repository lock, in-memory credentials, and recognizing sign-in failures.
store.rsThe imported-repository list (repos.json).

Frontend (web/)

Plain HTML, CSS and JavaScript, with no framework, bundler or npm packages at runtime.

  • app.js: state, rendering, dialogs, the graph's windowed SVG drawing, the conflict and rebase editors.
  • diff.js: the diff parser and renderer, the small syntax highlighter, word-level diffs, and the patch builder for partial staging. It also loads in Node, which is how it's tested.

Graph layout

The server lays out the graph so the browser only draws it:

  • Commits arrive in topological order (children first). graph.rs keeps a list of lanes, each waiting for a particular commit.
  • A commit takes the leftmost lane waiting for it. Other lanes waiting for it curve in, and lanes it isn't involved with pass straight through.
  • Its first parent continues down the same column, and extra parents get new lanes.
  • Each row comes back with its column, color and line segments. Because lanes never move sideways, the browser can draw any window of rows on its own. That's what makes huge histories fast.

Helper modes

git sometimes needs to call a program back. DevTree is that program, run in a special mode:

ModeUsed asPurpose
devtree credential-helper getcredential.helperAnswers git's sign-in question with credentials typed into the UI (passed via the environment).
devtree write-todo <file>GIT_SEQUENCE_EDITORWrites the interactive-rebase plan you built.
devtree edit-message <file>GIT_EDITORFills in reworded commit messages during a rebase. Otherwise it leaves the message unchanged.

HTTP API

All routes are under /api, need the X-DevTree: 1 header and speak JSON. Errors look like {"error": "…"}. A remote sign-in failure returns 401 with an auth object, and a cancelled command returns 409. Network routes accept ?job=<id> for live progress via /api/jobs/<id>.

AreaRoutes
RepositoriesGET/POST /repos, POST /repos/clone, DELETE /repos/{id}, GET /fs
Viewsgraph, status, branches, remotes, commit/{sha}, commit/{sha}/diff, diff, blob, file
Working treestage, unstage, apply, discard, commit, stash, stash/{n}/{apply|pop|drop}
Branches & tagscheckout, branch, branch/{delete|rename|upstream}, tag, tag/{delete|push}
History editingmerge, rebase, rebase/plan, rebase/interactive, cherry-pick, revert, reset, operation/{continue|skip|abort}, resolve
Remotesfetch, pull, push, remote/{add|remove|rename|set-url}, remote-net/{fetch|prune}, /credentials, /jobs/{id}, /jobs/{id}/cancel
Exploringfile-history, blame, search, compare, compare/diff

Repository routes are /api/repos/{id}/…. The handlers in src/ document their request bodies.

Testing

$ cargo test                    # unit tests (parsers, lanes, conflict detection)
$ cargo build                   # the end-to-end tests drive target/debug/devtree
$ cd tests/e2e
$ npm install
$ npx playwright install chromium
$ npm test                      # end-to-end tests

Every end-to-end test gets:

  • its own DevTree server on a free port
  • temporary git repositories
  • an isolated git config

The tests then click through the real UI in Chromium, or call the API directly. The network tests run a small password-protected git server (tests/e2e/support/gitserver.py, which needs Python). Avatar services are faked, so nothing depends on the internet.

GitHub Actions runs formatting, clippy, the unit tests and the end-to-end tests on Linux, macOS and Windows for every push and pull request.

Code style

  • cargo fmt (with max_width = 160) and cargo clippy --all-targets -- -D warnings must pass.
  • Shell out to git rather than adding git libraries. Never build commands through a shell, and validate anything that becomes a git argument (see api.rs).
  • No runtime dependencies in the frontend. Keep it plain JavaScript.
  • Comments explain why, not what.

Pull requests

  1. Fork, then create a branch for your change.
  2. Add or update an end-to-end test for anything a user can see or do.
  3. Run cargo fmt, cargo clippy, cargo test and the end-to-end tests.
  4. Open a pull request that explains what changed and why. Screenshots help for UI changes.

This website

The site in site/ is plain HTML and CSS, deployed to Firebase Hosting by GitHub Actions. Pull requests that touch it get a preview link.

$ node scripts/check-site-links.mjs                  # broken links and anchors
$ npx firebase-tools emulators:start --only hosting  # preview at localhost:5000
# after UI changes, regenerate the screenshots in site/img:
$ cd tests/e2e
$ npx playwright test --config screenshots.config.js
