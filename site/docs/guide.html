User guide

A tour of everything DevTree can do. If you know GitKraken, most of it will feel familiar.

The window

  • Top bar: the repository, the current branch, whether you're ahead (↑) or behind (↓) the remote, and when you last fetched. On the right: Fetch, Pull, Push, Branch, Stash, Pop, refresh, and the light/dark switch.
  • Sidebar: your repositories, then the local branches, remotes (grouped by remote), tags and stashes of the open one.
  • Graph in the middle, and the details panel on the right for whatever you select.
  • Console at the bottom: click it to see every git command DevTree ran and its output.

Nearly everything has a right-click menu: commits, branches, tags, remotes, stashes and files.

Commit graph

Each branch gets a colored lane. Merges curve in, branches curve out. Nodes show the author's picture or initials. A ring marks your HEAD, and a hollow node marks a merge commit. Badges show branches (filled when checked out), remote branches (dashed) and tags (◆).

  • WIP row: uncommitted changes appear as a dashed node at the top. Click it to open the working tree panel.
  • Hover a commit to light up its line of history (its first-parent path).
  • Filter: type in the box above the graph (/) to dim commits that don't match by message, author or SHA. Press Enter to search all history instead.
  • Big repositories: only the rows on screen are drawn, and older history loads as you scroll down. A 30,000-commit repository stays smooth.

Author chips

The AUTHOR column and the graph nodes show who wrote each commit. Where pictures come from:

  • GitHub "noreply" emails (123+name@users.noreply.github.com) use the GitHub avatar.
  • Other emails use Gravatar.
  • If there's no picture, or you're offline, you get colored initials.

A ↻ after the name means someone else committed it, for example after a rebase, a cherry-pick or a merge on GitHub. Hover it to see who. The details panel shows both the author and the committer.

The ☺ button in the AUTHOR header turns pictures off. DevTree then fetches nothing. See privacy.

Who pushed?

Git doesn't record who pushed a commit, only its author and committer, so DevTree can't show it either.

Committing

Click the WIP row. The details panel becomes the working tree:

  • Unstaged and Staged files, each with STAGE / UNSTAGE buttons on hover, plus STAGE ALL / UNSTAGE ALL.
  • Click a file to see its diff.
  • Write a message (the counter turns red past 72 characters on the first line) and press Commit, or Ctrl/⌘+Enter.
  • Tick amend last commit to change the previous commit instead.

Partial staging

Open a changed file from the working tree, then:

  • Click lines to select them, and Shift-click to select a range. Then use Stage N lines, or Discard N to throw just those lines away.
  • Each hunk has STAGE HUNK and DISCARD HUNK buttons.
  • In a staged file's diff, the same works in reverse: Unstage N lines and UNSTAGE HUNK.

Line selection is turned off where a partial patch wouldn't apply cleanly: new, deleted and renamed files (stage the whole file instead), and while "ignore whitespace" is on.

Diff viewer

  • ◫ Split / ▤ Unified: side-by-side or inline. The choice is remembered.
  • Syntax colors for common languages, and word-level highlights showing exactly what changed within a line.
  • ␣ Whitespace hides whitespace-only changes.
  • Images (PNG, JPEG, GIF, WebP, SVG and more) show a before/after preview with their sizes.
  • History and Blame buttons jump to that file's history or blame.

Discard & stash

  • ↺ next to an unstaged file discards your changes to it (or deletes it, if it's new). Discard all in the working tree panel throws away everything. Both ask first.
  • Stash (toolbar or working tree) saves your changes with an optional message, including new files by default. Pop brings back the latest stash.
  • Stashes are listed in the sidebar. Click one to see its changes, with Apply, Pop and Drop buttons.
  • If uncommitted changes would block switching branches, DevTree offers Stash & switch.

Branches, tags & remotes

  • Check out a branch by double-clicking it in the sidebar or on its badge in the graph. A remote branch gets a local tracking branch.
  • Drag a branch onto another to merge or rebase. The menu offers what makes sense for those two branches.
  • Right-click a branch to:
    • merge it into your branch, or rebase your branch onto it
    • rename it, or set or unset its upstream
    • compare it with your branch
    • create a branch or tag there
    • delete it. DevTree asks again before force-deleting an unmerged branch, and can delete branches on the remote too.
  • Tags: create lightweight or annotated tags from a commit's menu (optionally pushing them), push one or all tags, and delete them locally or on the remote too.
  • Remotes: + next to REMOTE adds one. Click a remote's name to fetch it, prune deleted branches, edit its URL, rename or remove it.

Fetch, pull & push

  • Fetch updates all remotes. Its ▾ menu sets auto-fetch (off, or every 1, 5, 15 or 30 minutes; 5 by default). The top bar shows when you last fetched.
  • Pull uses the mode from its ▾ menu: fast-forward if possible (default), fast-forward only, or rebase. Local changes are stashed and restored automatically.
  • Push pushes your branch. A branch without an upstream is published and tracked automatically.
  • Network commands show a progress card with git's own progress and a Cancel button. Commands on the same repository wait their turn instead of colliding.
  • If a remote needs a password, DevTree asks you to sign in and retries. Background auto-fetches never pop up dialogs. If one needs a sign-in, the top bar says so, and clicking it fetches with the prompt.

Merge conflicts

When a merge, rebase, cherry-pick or revert stops on conflicts, a striped banner says what's happening (for example MERGING fix/timeouts into main · 1 conflicted file, or REBASING … step 2/5). The banner has:

  • Resolve conflicts: opens the conflict editor. Each conflict is shown side by side: CURRENT (your side) and INCOMING.
    • Choose Use current, Use incoming, or Both (in either order).
    • Or click Edit manually to write the result yourself.
    • Save & mark resolved moves on to the next conflicted file.
    • Binary files, and files deleted on one side, offer Keep current file or Take incoming file.
  • Continue (or Commit merge): enabled once nothing is conflicted.
  • Skip: drops the current commit (rebase, cherry-pick and revert only).
  • Abort: goes back to where you were before it started.
"Current" during a rebase

During a rebase, "current" is the branch you're rebasing onto, and "incoming" is your own commit being replayed. The editor reminds you.

Interactive rebase

Right-click a commit on your branch and choose Interactive rebase from here…. The editor lists the commits after it, oldest at the top, in the order they'll be replayed:

  • Drag ⣿ (or use ▲▼) to reorder.
  • Pick an action per commit:
    • pick keeps the commit
    • reword keeps it with a new message (starting from the current one)
    • squash melds it into the commit above and combines their messages
    • fixup melds it in and keeps only the message above
    • drop removes it
  • A summary line shows what will change. DevTree won't start a plan that can't work, such as squashing the first commit. It also warns that merge commits in the range will be flattened.

If the rebase stops for conflicts, resolve them and press Continue. Your reworded messages are still applied.

Cherry-pick, revert & reset

Right-click any commit:

  • Cherry-pick onto branch copies the commit onto your branch.
  • Revert this commit… adds a new commit that undoes it. This is safe on shared branches.
  • Reset branch to here… moves your branch:
    • soft keeps the changes staged
    • mixed keeps them unstaged
    • hard throws them away (it asks once more if you have uncommitted work)
  • Also: check out the commit (detached), merge it or rebase onto it, create a branch or tag there, and copy its SHA or message.

History, blame & search

  • File history: right-click any file (or use History in a diff). It lists every commit that changed the file, following renames. Pick one to see its diff, open the commit, or blame the file at that point.
  • Blame: each line's author and date, grouped by commit, brighter for more recent changes. Click a line to open its commit.
  • Search all history: choose a mode next to the filter box and press Enter. Modes:
    • message
    • author (name or email)
    • sha
    • file (file or folder name)
    • code: commits that added or removed the text
    It searches all branches, not just what's loaded in the graph.

Compare

Select a commit, then Ctrl/⌘-click a second one, or choose Compare with branch from a commit's or branch's menu. The details panel shows:

  • the files that differ (click one for its diff)
  • the commits only on each side
  • a ⇄ SWAP button
