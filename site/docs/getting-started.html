Getting started

Build DevTree, open it, and point it at a repository. It takes about a minute.

Requirements

  • git 2.30 or newer, on your PATH. DevTree runs your installed git, so your config, SSH keys and credential helper all apply.
  • Rust, to build from source (not needed for the Windows download): a recent stable toolchain (DevTree uses the 2024 edition). Install it with rustup.
  • Your system's web engine, which draws the window: WebView2 on Windows 10 and 11 and WebKit on macOS come with the system. On Linux, install WebKitGTK (see the install guide).

DevTree runs on Linux, macOS and Windows. All three are tested on every change.

Downloads

Windows users can download DevTree and skip Rust. On macOS and Linux, build from source for now. It's one command.

Install

Follow the install guide for step-by-step instructions for macOS, Linux or Windows. In short, once git and Rust are installed:

$ git clone https://github.com/ErmanDev/DevTree.git
$ cd DevTree
$ cargo install --path .

Run DevTree

$ devtree
🌳 DevTree running at http://localhost:7878  (close the window to quit)

DevTree opens in its own window. Close the window to quit.

Behind the window, DevTree runs a small web server on your own machine, and the window shows its page. Only your computer can reach it: it listens on 127.0.0.1. Prefer a browser tab? Start DevTree with devtree --browser, and press Ctrl+C in the terminal to stop it.

From a clone of the source you can also just run cargo run --release.

Command-line options

OptionDefaultWhat it does
--port <n>7878Port to listen on (always on 127.0.0.1). 0 picks any free port. Without this option, the window uses another free port if 7878 is taken.
--data-dir <path>~/.devtreeWhere DevTree keeps its list of imported repositories. You can also set DEVTREE_HOME.
--clone-dir <path>~/devtree-reposDefault folder for repositories you clone from a URL.
--browserOpen DevTree in your web browser instead of its own window.
--no-openOpen nothing; just run the server. Visit http://localhost:7878 yourself.
--helpShow usage.

Your first repository

Click + ADD in the sidebar (or Add repository on the empty screen). You can either:

  • Open a local repo: browse to a folder (git repositories are marked ●) and click Import, or double-click it.
  • Clone from a URL: paste an HTTPS or SSH URL. It's cloned into your clone folder, with live progress and a Cancel button.

DevTree remembers imported repositories and reopens the last one next time. Removing a repository from the list (✕ next to its name) never touches its files.

Tip

Press / to filter the graph, j/k to move between commits, and r to refresh. See all keyboard shortcuts.

Signing in to remotes

Public repositories need no sign-in. For private ones, DevTree uses whatever already works with git on your machine, and asks only when it has to.

HTTPS & personal access tokens

When a server asks for credentials, DevTree shows a Sign in to github.com dialog and retries once you've entered them. GitHub, GitLab and Bitbucket don't accept your account password here. They need a personal access token:

  1. On GitHub, open Settings → Developer settings → Personal access tokens → Fine-grained tokens and generate a token.
  2. Give it access to the repositories you need, with Contents: Read and write if you want to push.
  3. In DevTree's dialog, enter your username and paste the token as the password.

Credentials are kept in memory only: for one operation, or until DevTree closes if you tick "Remember". If you have a git credential manager installed, it saves them permanently as usual. See how credentials are handled.

A mistyped repo name also asks you to sign in

GitHub answers the same way for private and non-existent repositories, so a typo in a clone URL also shows the sign-in dialog. Check the URL first.

SSH keys

SSH URLs such as git@github.com:you/repo.git use your normal SSH setup, with no dialog. If the server rejects your key, DevTree explains what to check:

$ ssh-add -l              # is a key loaded?
$ ssh-add                 # load your key (asks for its passphrase)
$ ssh -T git@github.com   # accept the host key once, test the login

DevTree runs ssh in batch mode, so it fails with a clear message instead of waiting on a prompt you can't see. If you've configured your own core.sshCommand or GIT_SSH_COMMAND, it is left alone.

Updating & uninstalling

See Updating and Uninstalling in the install guide. Removing DevTree never modifies your repositories.

Troubleshooting

"cannot listen on 127.0.0.1:7878: Address already in use"

Another DevTree (or another program) is using the port. Stop it, or start with devtree --port 7979.

The window doesn't open, or stays empty

See the install troubleshooting for your system. You can always use devtree --browser, or devtree --no-open and open http://localhost:7878 yourself.

"failed to start git"

git isn't on the PATH of the terminal you started DevTree from. Check with git --version.

Pull says "Not possible to fast-forward"

You chose Fast-forward only in the Pull ▾ menu, but both you and the remote have new commits. Pick Fast-forward if possible (merges when needed) or Rebase instead.

Something else

Open the Console at the bottom of the window. It shows every git command DevTree ran and its full output. Then open an issue with what you see.
