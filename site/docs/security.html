Security & privacy

DevTree runs git commands on your computer on behalf of a web page. This page explains how it keeps that safe, and what it does and doesn't send anywhere.

The model

DevTree is a local program with a web UI. Its window (or, with --browser, a browser tab) shows a page that asks the DevTree server, running on your machine, to run git. The server must therefore only ever take orders from that page:

  • not from other computers on your network
  • not from other websites open in your browser
  • not through input crafted to sneak extra options into a git command

A server only you can reach

  • Loopback only. The server listens on 127.0.0.1, so other machines can't connect to it.
  • Host check. Requests whose Host isn't localhost, 127.0.0.1 or [::1] are refused. This blocks DNS rebinding, where a malicious site points its own domain name at your machine.
  • A custom header on every API call. The API rejects requests without an X-DevTree header. Browsers won't let another website add a custom header to a request to a different site without the server's permission (a CORS preflight), and DevTree never gives it. So a website you visit can't drive your git, even though it can reach localhost.
  • The window only shows DevTree. The desktop window loads nothing but DevTree's own local pages. Web links open in your default browser, and links of any other kind (local files, custom schemes) are ignored, so a page can't make DevTree start another program.
  • Sandboxed previews. File contents served for image previews carry Content-Security-Policy: sandbox and nosniff, so an SVG in a repository can never run script in DevTree's page.

Running git safely

  • No shell. git is started directly with a list of arguments, never through a shell, so characters like ; or $( ) in names have no special meaning.
  • No option injection. Branch, tag and remote names, commit IDs and URLs that start with - (for example --upload-pack=…) are rejected. File paths always come after --.
  • Paths stay inside the repository. File paths must be relative and can't contain ... The conflict editor may only write files that are actually in conflict.
  • No hidden prompts. git never prompts in a terminal (GIT_TERMINAL_PROMPT=0), and ssh runs in batch mode unless you've configured your own ssh command. Long network commands have a timeout, and Cancel stops git together with its helper processes.

Credentials

When a remote asks you to sign in, here is what happens to the username and token you type:

  • They are kept in memory only, never written to disk by DevTree. They're used for one operation, or until DevTree closes if you tick "Remember".
  • They reach git through DevTree itself acting as a git credential helper (devtree credential-helper get). The secret is passed in that one child process's environment, never on a command line where other programs could see it.
  • Your own credential helpers (for example Git Credential Manager or the macOS keychain) are asked first, and may save what you type, exactly as they would for plain git.

Author pictures

Author chips show pictures, which come from other services:

  • For GitHub "noreply" addresses, your browser loads the picture from avatars.githubusercontent.com or github.com.
  • For other addresses, it asks gravatar.com for a picture using a SHA-256 hash of the commit author's email, not the email itself.

Requests are sent without a referrer. Gravatar can still recognize a hash it already knows. If you'd rather your browser didn't contact these services, click ☺ in the AUTHOR column header. DevTree then shows initials only and makes no such requests. The setting is remembered.

What DevTree stores

  • ~/.devtree/repos.json (or your --data-dir): the list of repositories you imported (name and path). Nothing else.
  • UI preferences such as the theme, pull mode, auto-fetch interval, diff layout and the last opened repository, in the page's local storage: in ~/.devtree/webview for the desktop window, or in your browser.
  • During an interactive rebase, .git/devtree-reword.json in that repository holds your new commit messages. It is removed when the rebase ends.

There is no telemetry, no analytics, no crash reporting and no account.

Network connections

DevTree itself only ever talks to:

  • your git remotes, when you (or auto-fetch) fetch, pull, push or clone
  • avatar services, as described above, unless you turn pictures off
  • Google Fonts, which the UI loads its retro fonts from. Without it, it falls back to your system fonts.
  • GitHub's release API, once each time DevTree starts, to see whether a newer version is out. Updates are only downloaded when you click Update now, only from DevTree's own GitHub releases, and only installed if the file matches the release's SHA-256 checksum. Set DEVTREE_NO_UPDATE=1 to turn the check off.

Auto-fetch can be turned off in the Fetch ▾ menu.

Reporting a vulnerability

Please don't open a public issue for security problems. Use GitHub's private vulnerability reporting for the repository instead. Include what you found, how to reproduce it, and which version you used.
